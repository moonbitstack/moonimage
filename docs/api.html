The limits default to Limits::default(); a caller reading untrusted files should pass Limits::strict() or a tighter record.

The image as bytes of the named format, with that format's defaults.

function pub fn encode_animation(animation : @raster.Animation, format : @raster.Format) -> Bytes raise @raster.Refused

The animation as bytes of the named format, with that format's defaults.

The formats that animate keep every frame; the ones that do not write the first, which is what a viewer of a still image shows.

struct pub(all) struct Animation

A sequence of frames over one canvas.

  • widthInt32 The canvas width every frame is placed on.
  • heightInt32 The canvas height every frame is placed on.
  • loopsInt32 How many times the animation plays. 0 means forever, which is what an animation without a repeat count means in all three formats.
  • framesArray[Frame] The frames, in order.
  • metadataMetadata Metadata that belongs to the animation as a whole.
pub fn Animation::compose(self : Animation) -> Array[Image]

Every frame as a full canvas, in order, with each rule applied as it goes.

The result is what a viewer shows: the same length as frames, each one the whole canvas. This is the expensive way to watch an animation and the only way to see it out of context, which is what a test does.

The canvas is sixteen-bit, so that an eight-bit animation and a sixteen-bit one come out of the same code without either losing its precision.

Straight alpha, as stored: an image that says it is premultiplied returns premultiplied samples, because pretending otherwise would be a conversion the caller did not ask for.

pub fn Image::scale(self : Image, width : Int32, height : Int32, sampling? : Sampling) -> Image raise Refused

The image at a new size.

Raises when either dimension is not positive, and when the result would be larger than Limits::default() — a scaler is easy to point at a huge size by accident.

pub fn Image::to_premultiplied(self : Image) -> Image

The same image with colour multiplied by alpha.

Idempotent: an image that already says it is premultiplied comes back unchanged, so a caller can ask without checking first.

pub fn Image::to_straight(self : Image) -> Image

The same image with alpha divided back out.

The inverse of to_premultiplied up to rounding, which is why a round trip is only exact for images whose colour is already premultiplied.

struct pub(all) struct Limits

The ceilings a decoder works under.

The defaults are the ones a desktop application can live with: a texture no larger than a modern GPU takes, and a megabyte of pixels at the very most. A caller reading files from the network should set them lower; a caller reading its own assets can leave them alone.

  • widthInt32 The widest image accepted, in pixels.
  • heightInt32 The tallest image accepted, in pixels.
  • pixelsInt32 The most pixels accepted, whatever the shape: this is the one that stops a long thin image from slipping past the two above.
  • bytesInt32 The most bytes a decoder may produce while unpacking: a compressed stream can expand without limit, so the expansion is capped separately.
pub fn Limits::allows(self : Limits, width : Int32, height : Int32) -> Bool

Whether an image of this shape is inside the limits.

pub fn Limits::check(self : Limits, width : Int32, height : Int32) -> Unit raise Refused

Refuse an image of this shape unless the limits allow it.

The pixel count is multiplied in 64 bits so that a declaration of 65535 × 65535 cannot wrap into a small number and pass.

pub fn Limits::check_bytes(self : Limits, bytes : Int32) -> Unit raise Refused

Refuse a buffer of this many bytes unless the limits allow it.

pub fn Limits::default() -> Limits

The desktop defaults: a million pixels a side, 256 megapixels in all, and a gigabyte of expansion.

pub fn Limits::strict() -> Limits

What a viewer of untrusted uploads would choose: 8192 square, 64 megapixels, 256 MiB of expansion.

enum pub(all) enum PixelFormat

How the samples of an image are laid out.

The names are the usual ones: Gray8 is one byte per pixel, Rgba8 four, Rgba16 eight with each channel big-endian, RgbaF32 four floats.

  • Gray8 One sample, 8 bits.
  • GrayAlpha8 Grey and alpha, 8 bits each.
  • Rgb8 Three samples, 8 bits each, red first.
  • Rgba8 Four samples, 8 bits each, red first, alpha last.
  • Gray16 One sample, 16 bits, big-endian.
  • GrayAlpha16 Grey and alpha, 16 bits each.
  • Rgb16 Three samples, 16 bits each, big-endian.
  • Rgba16 Four samples, 16 bits each, big-endian.
  • RgbaF32 Four samples as Float, 0–1, little-endian.

error pub(all) suberror Refused

A refusal to read bytes as an image, or to write an image as bytes.

The variants separate the three questions a caller asks: is this the wrong kind of file (Unknown), is the file damaged (Unexpected, Truncated, Checksum), or is the caller asking for more than it allowed (OverLimit). Unsupported is the fourth: a part of a format this library does not read.

  • Unexpected(at~ : Int32, got~ : String, want~ : String) The bytes at at are not allowed here; want says what is.
  • Unknown(at~ : Int32, got~ : String) Nothing at at is an image this library reads.
  • Unsupported(at~ : Int32, got~ : String) A part of the format this library does not read.
  • Truncated(at~ : Int32, want~ : Int32) The bytes end want short of where the format needs them.
  • OverLimit(limit~ : Int32, got~ : Int32) A size or a length past what the caller's Limits allow.
  • Checksum(at~ : Int32, got~ : String, want~ : String) A checksum that does not match the bytes it covers.

How a scaler decides what an unknown pixel is worth.

  • Nearest The nearest pixel, and nothing else: no new colours.
  • Bilinear A weighted average of the four nearest, weights linear in distance.

enum pub(all) enum Subsampling

How much of the colour resolution to give up.

The eye resolves brightness far better than hue, so the two colour channels are stored at half resolution or a quarter, which is where most of JPEG's size comes from.

  • Yuv444 Full resolution in all three channels.
  • Yuv422 Colour at half horizontal resolution.
  • Yuv420 Colour at half resolution both ways, which is what a camera writes.

struct pub(all) struct EncodeOptions

What to trade when writing a PNG.

  • levelInt32 Deflate level, 0 to 9.
  • filterFilter How rows are filtered before deflating.
  • interlaceBool Whether to write the image in seven passes, which helps a viewer show something before the last byte arrives and makes the file slightly larger.
  • metadataBool Whether to write the metadata the image carries.
  • paletteBool Whether to write a picture of at most 256 colours as a palette. A palette costs a table of colours and saves three quarters of every pixel, which is the difference between a sprite and a photograph in one flag.

enum pub(all) enum Filter

Which row filter an encoder uses.

Adaptive is the one the specification recommends: try all five, keep the one whose output has the smallest sum of absolute differences. It costs four extra passes over each row and usually pays for itself several times over in what the compressor then has to store.

  • Adaptive Pick per row.
  • None Store the row as it is.
  • Sub Subtract the pixel to the left.
  • Up Subtract the pixel above.
  • Average Subtract the average of the two.
  • Paeth Subtract the one the Paeth predictor picks.

webp WebP

Lossless and lossy pictures, the alpha chunk that travels beside a lossy one, and animation.

functions

The image in a WebP file.

function pub fn decode_alpha(payload : BytesView, width : Int32, height : Int32, limits : @raster.Limits) -> Bytes raise @raster.Refused

The alpha plane that travels beside a lossy picture.

VP8 codes no alpha, so a transparent lossy WebP carries a separate ALPH chunk: one byte saying how it is stored, then the plane — raw, or compressed with the *lossless* codec, in which case the samples sit in its green channel — then a filter along each row, the same idea as PNG's and undone the same way. The result is one byte per pixel, which is all an alpha channel is.

function pub fn decode_animation(bytes : BytesView, limits? : @raster.Limits) -> @raster.Animation raise @raster.Refused

Every frame of an animated WebP.

A still picture comes back as an animation of one frame covering the whole canvas, which is what every other format here does and what lets a caller hand any WebP to one code path.

function pub fn decode_lossless(payload : BytesView, limits : @raster.Limits) -> @raster.Image raise @raster.Refused

function pub fn decode_lossless_stream(payload : BytesView, width : Int32, height : Int32, limits : @raster.Limits) -> @raster.Image raise @raster.Refused

The image in a lossless *stream*: the part of a VP8L file that comes after its five-byte header, with the size supplied by the caller.

A lossy WebP codes its alpha channel this way, in a separate ALPH chunk whose size is the picture's own, which is why there is no header to read.

function pub fn decode_lossy(payload : BytesView, limits : @raster.Limits) -> @raster.Image raise @raster.Refused

The image in a VP8 payload: a frame header, then the compressed frame.

The header is in the first partition, interleaved with the macroblock modes; the coefficients are spread over up to eight partitions, one per row of macroblocks in rotation, which is what lets a decoder read them in parallel.
